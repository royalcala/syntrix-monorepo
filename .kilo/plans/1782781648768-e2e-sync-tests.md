# E2E P2P Sync Integration Tests

## Objective

Replace manual GUI testing with headless multi-node integration tests that catch every sync bug. Target: app blindada — all P2P flows, role enforcement, restart recovery, and edge cases verified without opening the GUI.

---

## Architecture Decision

**Single process, 3× AppState** (admin + client1 + client2) per test. All bind `0.0.0.0:0` (random ports), communicate via localhost iroh QUIC. Single process catches all application-logic bugs. Network-layer bugs (relay, NAT, packet loss) are iroh's responsibility.

Each test uses `syntrix_testkit::temp_node_dir(prefix)` for isolated `data_dir` per AppState. No state leaks between tests.

---

## Phase 1 — Create Missing `*_impl` Wrappers

The convention requires every `#[tauri::command]` to delegate to a `pub *_impl(state, ...)` function. Three commands lack this, blocking headless tests.

### 1.1 `client::join_org_impl` — `apps/client/src-tauri/src/lib.rs`

Extract the body of `async fn join_org()` Tauri command into:

```rust
pub async fn join_org_impl(
    state: &mut AppState,
    invite_json: &str,
    org_name: Option<&str>,
) -> Result<OrgInfo, String>
```

The `#[tauri::command]` becomes a thin wrapper:

```rust
#[tauri::command]
async fn join_org(state: tauri::State<'_, Mutex<AppState>>, invite_json: String, org_name: Option<String>) -> Result<OrgInfo, String> {
    let mut s = state.lock().map_err(|e| e.to_string())?;
    join_org_impl(&mut s, &invite_json, org_name.as_deref()).await
}
```

### 1.2 `client::get_endpoint_addr_impl` — `apps/client/src-tauri/src/lib.rs`

```rust
pub fn get_endpoint_addr_impl(state: &AppState) -> String {
    let addr = state.endpoint().addr();
    let addrs: Vec<String> = addr.addrs.iter().map(|a| a.to_string()).collect();
    serde_json::json!({
        "node_id": hex::encode(state.node_id()),
        "addrs": addrs,
    }).to_string()
}
```

### 1.3 `admin::get_endpoint_addr_impl` — `apps/admin/src-tauri/src/admin.rs`

### 2.3 `invite_and_join(admin, client, org, role) -> Result<()>`
```rust
pub async fn invite_and_join(
    admin: &mut AdminState,
    client: &mut ClientState,
    org_name: &str,
    role: &str,
) -> anyhow::Result<()>
```

Flow:
1. Get client addr via `get_endpoint_addr_impl(client)`
2. Get invite_info from admin
3. Admin sends invite via `admin::send_invite(...)`
4. Client drains pending invites via `get_invites_impl(client)`
5. Client joins via `join_org_impl(client, invite_json, Some(org_name))`

### 2.4 `wait_for_document(entity, doc_id, indexer, org, timeout) -> Result<Value>`
Polls via `query_entity_impl` until a document with `id == doc_id` appears.

### 2.5 `count_events(indexer, org) -> usize`
Counts all events in EVENT_LOG for a given org.

### 2.6 `wait_for_audit_entry(state, org, doc_id, timeout) -> Result<AuditEntry>`
Polls `admin::audit_query` until an entry with matching `doc_id` appears.

## Phase 3 — Required Fixes Before Certain Tests

These are implementation tasks — the tests in Layer 2, 3, and 5 depend on them.

### Fix A — Read enforcement in `query_entity_impl`

**File**: `apps/client/src-tauri/src/lib.rs:347`
**Gap**: `check_read_access()` exists (line 300) but is never called from `query_entity_impl`. Any client can read any entity regardless of role's `can_open`.
**Fix**: Add `check_read_access(state, &resolved_org_id, entity)?;` at the start of `query_entity_impl` (after entity != "roles" check).

### Fix B — Broadcast role changes via gossip

**Files**: `apps/admin/src-tauri/src/admin.rs`, `apps/admin/src-tauri/src/identity.rs`
**Gap**: `create_role` / `update_role` only update admin's local memory. Role changes never reach clients.
**Fix**: After `state.set_role(...)`, broadcast a `role.updated` event via gossip bus so all clients in the org topic receive it. The client's gossip receiver already processes events — add handling for `role.updated` to update local redb roles (via `indexer.upsert_role_cfg`).

### Fix C — Broadcast device reassignment via gossip

**Files**: `apps/admin/src-tauri/src/admin.rs`
**Gap**: `update_device` (changing role/active status) only updates admin. Client keeps old role.
**Fix**: After `state.update_device(...)`, broadcast a `device.updated` event via gossip. Client receiver updates local registry and indexer when receiving it.

### Fix D — Admin catchup client on restart

**Files**: `apps/admin/src-tauri/src/identity.rs`, new file or inline logic
**Gap**: Admin has `AdminCatchupProtocol` (server) but no client to request catchup from peers after restart. Admin's EVENT_LOG is incomplete if it was offline during commits.
**Fix**: On admin restart (inside `new_with_data_dir`, after re-joining gossip topics), implement catchup: wait for heartbeats from online peers, then request events via direct iroh connection (similar to client's `CatchupProtocol::request_catchup`), storing results in admin's redb EVENT_LOG. Admin doesn't have a `RelationalEngine` — it uses redb directly (`write_event_to_redb` pattern already exists in `gossip.rs`).

## Phase 4 — E2E Test Scenarios (23 tests)

All in `apps/admin/src-tauri/tests/e2e_sync_test.rs`. Use `#[tokio::test]`, `syntrix_testkit::temp_node_dir`, `poll_until`.

### Layer 1 — Sync básico (7 tests, no fixes needed)

**Test 1 — `test_two_clients_sync_via_gossip`**
- Admin crea org "acme"
- Admin invita client1 y client2 (both role "sales")
- Client1 commitea `customer.created` `{id: "c1", name: "Acme"}`
- `poll_until` verifica: client2 `query_entity("customers", id="c1")` retorna el documento
- Admin `audit_query(org="acme", doc_id="c1")` retorna 1+ entrada

**Test 2 — `test_client_restart_catches_up_via_admin`**
- Admin + client1 online, client2 online
- Dropear `client2_state` (simula app cerrada)
- Client1 commitea `customer.created` `{id: "c2"}`
- Crear nuevo client2 con `new_with_data_dir(client2_data_dir)` (simula app reabierta)
- `poll_until` verifica: client2 tiene documento "c2"
- Verifica `count_events(client2_indexer) >= 1`

**Test 3 — `test_admin_audit_sees_propagated_events`**
- Admin + client1 online
- Client1 commitea `product.created` `{id: "p1", name: "Widget"}`
- `poll_until` → `admin::audit_query(org, filter={entity:"products"})` tiene 1+ entrada con `event_type == "product.created"` y `doc_id == "p1"`

**Test 4 — `test_duplicate_event_prevention`**
- Admin + client1 online
- Client1 commitea evento con HLC `{ts, count, node}` — guardado
- Insertar manualmente el mismo HLC vía `indexer.upsert_document_with_hlc`
- Verificar `count_events(indexer) == 1` (HLC tracker rechazó duplicado)

**Test 5 — `test_disconnect_and_reconnect`**
- Admin + client1 + client2 online
- Client1 commitea → client2 lo recibe
- Dropear `client2.gossip_bus` (simula desconexión de red)
- Client1 commitea otro evento
- Client2 re-join gossip topic
- `poll_until` → client2 recibe evento pendiente vía gossip (admin estaba online, tiene el evento)

**Test 6 — `test_multi_org_isolation`**
- Admin crea org "acme" y org "beta"
- Client1 join "acme", client2 join "beta"
- Client1 commitea en "acme" → `poll_until` verifica NO aparece en client2
- Client2 commitea en "beta" → `poll_until` verifica NO aparece en client1
- Admin `audit_query("acme")` solo muestra eventos de acme

**Test 7 — `test_cold_start_full_recovery`**
- Admin + client1 + client2 online
- Client1 commitea 2 eventos
- Dropear los 3 AppState (simula cierre total)
- Re-crear los 3 con same data_dirs
- `poll_until` → admin tiene eventos en audit (catchup desde algún peer)
- `poll_until` → client2 tiene eventos (catchup desde admin)
- Verificar que los 3 nodos convergen al mismo estado

## Risks & Notes

1. **`syntrix-testkit` circular dependency**: Adding `syntrix-admin` or `syntrix-client` as deps to testkit would create a cycle. Helpers go directly in test files instead.

2. **iroh port binding**: All 3 AppState bind `0.0.0.0:0`. On same machine, QUIC discovers peers via localhost. `CaRootsConfig::insecure_skip_verify()` already set — required for testing.

3. **Timing**: Gossip propagation may take seconds. Use `poll_until` with generous configs: 50 retries, 200ms base delay, 5s max delay.

4. **Test isolation**: Each test uses `temp_node_dir()` — separate data_dir per AppState. No shared state.

5. **Fix B, C, D complexity**: Fixes B and C require modifying the gossip receiver to handle new event types (`role.updated`, `device.updated`). Fix D requires admin to open iroh connections to peers — uses the same pattern as client's `request_catchup`.

6. **Out of scope**: Relay failure, NAT traversal, cross-machine latency, GUI rendering, WebView behavior, multi-language i18n.
